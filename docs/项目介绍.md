# SmartFactory Twin 项目介绍

> 面向读者（评委、面试官、同行）的项目说明。运行与安装说明见根目录 `README.md`；
> 完整实验设计见 `docs/方案.md`，逐批实测见 `docs/acceptance_*.md`。

## 一、项目定位

SmartFactory Twin 是一个以**虚拟机械加工工厂**为场景的数字孪生演示系统：

- **工厂设定**：1 工厂 / 2 车间（WS-A、WS-B）/ 4 生产线（LINE-A1~B2）/
  14 台设备——12 台核心设备（CNC 数控机床 ×4、ROB 机器人 ×4、CONV 传送带 ×2、
  INSP 检测台 ×2）+ 2 台辅助设备（AIR-01 空压机、PUMP-01 冷却泵）。
- **核心命题**：把「数据生成 → 存储压缩 → 在线推理 → 可视呈现」整条链路做完整，
  并且让每一环都能被**实测验证**而不是口头声称。
- **用途**：本科毕业设计、GitHub 作品集；第一版全部数据为**模拟数据**，
  AI 输出为辅助参考，不得对外表述为真实工厂数据。

## 二、系统组成

### 1. 数据链路（模拟器 → 时序库 → 页面）

- **模拟器**（`data_pipeline/`）：按设备状态机生成温度 / 振动 / 电流 / 转速四指标遥测，
  每个 tick 批量 POST 给后端；支持三类异常注入（振动 / 电流 / 温度漂移）并同步写
  ground truth；驱动生产订单按节拍推进。
- **后端**（`app/`，FastAPI）：18 组 REST 接口 + WebSocket 快照推送；
  告警引擎按 `config/devices.json` 的阈值扫描告警，并按 G-10 规则自动收敛
  （指标峰值回落 60 秒后自动解除，页面写明这一口径）。
- **数据库**（TimescaleDB 2.17.2 / PostgreSQL 16，Docker 单容器）：
  10 张表，`device_telemetry` 为 hypertable 并启用压缩。

### 2. 前端五个页面（React 18 + Three.js + ECharts）

| 页面 | 路由 | 内容 |
|---|---|---|
| 工厂总览 | `/overview` | 纯三维展示页：车间室内化场景，产线随设备状态实时运行；7 个镜头预设、点击设备跳转监控页、自动巡游 |
| 设备监控 | `/devices` | 四指标实时曲线 + WARNING/CRITICAL 参考线，1h/6h/24h 切换 |
| 生产数据分析 | `/production` | 计划 vs 实际产量对比、合格率/完成率趋势、订单列表 |
| 设备告警与维护 | `/alerts` | 未解除告警 KPI、告警列表（分页）、维护记录登记 |
| 工厂日报 | `/ai` | 异常检测模型输出 + 今日拾份 / 交付风险；每个数字都追到 `/ml/*` 真实返回 |

### 3. 三维场景（项目着力最多的一层）

- **设备建模 v2**：14 台设备全部程序化建模（Blender 参数化生成 GLB + 运行时烘焙合并），
  每台含门、观察窗、操作面板、急停、散热格栅等 10~28 类可辨识部件；
- **场景合批**：灯、环用 `InstancedMesh` + `instanceColor`，墙与色带 `mergeGeometries`，
  工业道具（基座 / 护栏 / 警示带 / 线槽 / 货架 / 安全标识）逐类合并，
  让"细节变多"不以 draw call 为代价；
- **产线动画**：物料沿产线一维队列推进（纯函数算法，可单测），设备停机时物料在上游
  排队，滚筒自转、机械臂摆动，WebSocket 断开时整场冻结；
- **渲染管线**：ACES 色调映射 + Bloom + SMAA 后处理，程序化贴图（混凝土 / 墙板 / 地面），
  页面状态栏实时显示 fps 与 draw call。

### 4. AI 异常检测（第 4 阶段 A）

- **训练**：7 天回填数据（约 423 万行）→ 78 维统计特征 → 84.8 万行训练集
  （时间切分最后 15% 为测试集，杜绝随机切分的虚高）；
- **主模型** XGBoost：PR-AUC **0.9859** / Recall **0.9830** / Precision **0.9063**；
  阈值规则基线 0.9098 / 0.8028；另做四模型对比与三分类归因；
- **在线推理**：后端 `ml_anomaly.py` 懒加载模型 artifact，窗口推理，
  模型缺失时接口与页面**整栏降级并写明原因**，不显示占位数字；
- **诚实边界**：AI 输出为辅助参考；AI 页与报告中的每个数字都可追到一次真实返回。

## 三、关键技术决策与实测结果

| 决策 | 结果（可复跑） |
|---|---|
| `device_telemetry` 迁移 TimescaleDB hypertable | 4,570,704 行迁移前后完全一致（六步迁移 + 四项校验） |
| 启用原生压缩 | 1,001 MB → **234 MB**（总量 3.97:1，表口径 6.63:1） |
| 查询收益分类型评估 | 扫描类 -31%~-47%，点查类基本不变——不为压而压 |
| 随机切分对照实验 | 虚高 +0.0123 PR-AUC，写成偏差条目警示 |
| 前端渲染合批 | 灯 / 环 / 墙 / 色带 / 道具逐类合并或实例化，先压 draw call 再上细节；页面状态栏实时显示 fps 与 draw call 供验收核对 |
| 文档驱动 + 偏差登记 | 每条与规格的偏差都编号登记（D-11 起），被实测推翻的旧判断保留痕迹不静默修改 |

## 四、质量保障

- **后端接口测试**：pytest 25 用例（跑前须停 uvicorn，避免双进程抢写告警表）；
- **前端单测**：Vitest 195 用例 / 18 文件（含产线队列算法、道具几何约束、页面工具函数）；
- **页面级验收**：8 个 CDP 脚本驱动无头浏览器真点击，共 180+ 项断言
  （页面 24 / 动画 17 / AI 42 / 设备 54 / 视觉基调 9 / 工业道具 19 / 环境层 23 等）；
- **已知缺口如实登记**：三维页盲测（3 人 ≥2 人认出是工厂）需真人参与，尚未完成。

## 五、边界与后续

- **不做 / 已取消**：数据一致性验证、Kafka 接入、故障风险与产量预测（规格 v4.0 明确取消）；
- **简化声明**：三维模型为工程化简化，指标为模拟生成；
- **后续方向**：演示物料与性能收尾（D6）、更多真实感细节、答辩演示脚本。
