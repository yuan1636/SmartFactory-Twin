## 1. 结论摘要

一句话：**能跑、不卡，但"不像工厂"——它是「几个方块摆在发光的深色地板上」，不是车间。**

三个事实先摆出来：

| 维度 | 结论 | 依据 |
|---|---|---|
| **假** | 设备是 2~3 个纯色方块叠成，认不出是机床；传送带是半透明发光条，没有侧板与支腿 | `04_device.png`、`05_line.png` |
| **空** | 没有墙、没有屋顶、没有柱子、没有护栏/管道/货架/标识；地平线以上整片纯黑 | `01_overview.png`、`06_eye_level.png` |
| **卡** | **不卡**。144.9 fps、108 draw call、首屏 562 ms | `baseline.json` |

性能不是问题，**视觉密度与可辨识度是问题**。这与 v4.0 §2.3 的预期一致（瓶颈在 draw call 而非面数），
但"不卡"不代表"演得住"——D6 的 3 分钟稳定性与弱机帧率仍未验证。

## 5. 复现命令

```powershell
# 前提：后端 8000 / 前端 5173 / 窗口化 Chrome 9222（有 GPU）
node scripts/audit-baseline.mjs      # → output/d0/baseline.json
node scripts/audit-shot.mjs          # → output/d0/01..06.png + poses.json
node scripts/audit-record.mjs 30     # → output/d0/d0_30s.webm（录完自检非黑屏）
```

三条脚本都会在开头校验 `__sceneDebug` 是否存在；若跑在生产构建上会直接报"场景未就绪"，不会静默产出空图。
